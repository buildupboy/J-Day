# J-Day 스케줄링 발표 예상 질문 (쉬운 말 버전)

지금 실제로 만들어진 기능만 기준으로 썼습니다. 아직 없는 기능은 "앞으로 할 일"이라고 말하세요.

---

## 1. 우선순위 점수

**Q. 우선순위 공식은 어디서 가져왔나요?**
- 논문에서 가져온 공식이 아니라, 저희가 직접 만든 계산식입니다.
- 이미 널리 쓰이는 생각을 참고했습니다. 마감이 급한 것부터 하기, 짧은 것부터 하기, 중요한 것과 급한 것을 같이 보기입니다.
- 이 생각들을 하나의 점수로 합쳤습니다. "정답"이라고 검증한 값은 아니고, 필요하면 조정할 수 있는 처음 값입니다.

**Q. 0.4 / 0.2 / 0.3 / 0.1은 왜 그렇게 정했나요?**
- 마감이 급한지를 가장 크게 보고, 그다음 중요도, 일의 양, 일의 길이 순으로 봅니다.
- 실험이나 통계로 찾은 값은 아닙니다. "마감이 하루 늦어도 훨씬 중요한 일이 먼저 나오는지" 같은 상황을 테스트해서 의도대로 움직이는지만 확인했습니다.

**Q. 마감이 하루 차이인데, 늦은 쪽이 훨씬 중요하면요?**
- 마감 순서만 보지 않고 점수로 비교하기 때문에, 중요한 일이 먼저 올 수 있습니다.

**Q. 점수가 똑같으면요?**
- 마감이 빠른 것, 중요한 것, 남은 시간이 짧은 것, 먼저 입력한 것 순서로 정합니다.

**Q. 이미 마감이 지난 일은요?**
- 점수를 100점으로 해서 가장 먼저 다룹니다. 다만 지나간 시간에는 일정을 넣을 수 없어서, 자리를 못 잡을 수 있습니다.

**Q. 식에 나오는 480분은 뭔가요?**
- 하루에 일할 수 있는 시간을 8시간으로 가정한 값입니다. 실제 빈 시간을 계산한 것이 아니라 대략적인 값이고, 더 정확하게 계산하는 건 앞으로 할 일입니다.

## 2. AI가 하는 일과 믿을 수 있는지

**Q. 왜 규칙으로 안 하고 AI가 시간을 정하나요?**
- "운동 뒤에는 씻을 시간을 남기기", "큰 일은 며칠에 나눠서 하기"처럼 상황을 보고 정해야 하는 일은 규칙 몇 개로 쓰기 어렵습니다.
- 그래서 역할을 나눴습니다. 프로그램이 순서와 조건을 정리하고, AI가 시간을 정하고, 서버가 맞는지 확인합니다.

**Q. AI가 잘못된 시간을 주면요?**
- 서버가 확인해서 규칙을 어기면 받아주지 않고, AI에게 이유를 알려 주고 한 번 더 시킵니다. 그래도 안 되면 원래 일정을 그대로 둡니다.
- 서버가 확인하는 것은 이렇습니다.
  - 수업·알바·수면·쉬는 시간과 겹치는지
  - 일정끼리 겹치는지
  - 마감을 넘기는지
  - 지나간 시간인지
  - 한 번에 너무 오래 하는지
  - 하루 작업량이 넘는지
  - 작업 사이 쉬는 시간이 있는지
  - 남은 일보다 많이 넣었는지
  - 단계 순서가 맞는지

**Q. AI가 시간을 마음대로 고치지는 않나요?**
- 서버는 AI가 정한 시간을 몰래 바꾸지 않습니다. 맞으면 저장하고, 틀리면 거절합니다.

**Q. AI 답이 늦으면요?**
- 과제는 먼저 저장하고, 일정 짜기는 뒤에서 합니다. 시간이 너무 오래 걸려도 과제는 그대로 남아 있고, "다시 배치" 버튼으로 다시 시킬 수 있습니다.
- 실제로 몇 초 걸리는지 숫자로 재 본 것은 아직 없습니다.

**Q. API 키는 안전한가요?**
- 키는 서버(백엔드)에만 있고, 사용자 화면(프론트엔드)에는 없습니다.

## 3. 사용자가 정하는 것과 규칙

**Q. 하루 작업량 제한은 어떻게 지키나요?**
- 마이에서 고른 시간(2·4·6·8시간)을 넘기면 서버가 AI의 결과를 받아주지 않습니다. 이미 짜 둔 일과 끝낸 일도 같이 더해서 계산합니다. 수업 같은 고정 일정은 포함하지 않습니다.
- 제한을 낮게 잡으면 마감 안에 다 못 끝낼 수도 있고, 그때는 못 넣은 시간이 남습니다.

**Q. 쉬는 시간은 어떻게 하나요?**
- 작업 사이에 정해 둔 만큼 쉽니다. 수업이나 약속이 끝난 뒤에는 이동 시간과 쉬는 시간 중 더 긴 쪽을 비워 둡니다.
- 이동 시간이 정해진 일정은 서버가 꼭 지키게 합니다. 운동처럼 일정 성격에 따라 더 여유를 두는 건 AI가 판단하고, 서버가 그 길이까지 확인하지는 않습니다.

**Q. 마감이 먼 큰 일이 하루에 몰려 들어가지는 않나요?**
- AI에게 "마감까지 남은 날로 나눠서 하루 목표를 정하고, 같은 일을 하루에 연달아 붙이지 마라"고 시켜 두었습니다. 서버가 강제로 막는 규칙은 아니고, AI가 따르는 규칙입니다.

**Q. 쉬는 날도 정할 수 있나요?**
- 네. "토요일은 쉬고 싶어"라고 말하면 그날에는 새 일을 넣지 않습니다. 수업 같은 고정 일정과 이미 한 기록은 그대로 둡니다.

## 4. 사용 방법

**Q. 말로 여러 과제를 한 번에 등록할 수 있나요?**
- 네. 한 번에 여러 개를 말하면 하나씩 나눠서 등록합니다. 마감을 안 말한 과제만 골라서 다시 물어봅니다.

**Q. 걸리는 시간을 말하지 않으면요?**
- 저장하기 전에 먼저 물어봅니다. "제이가 정해줘"라고 하면 AI가 시간을 정하고 단계로 나눠 줍니다. 시간은 5분 단위로 나옵니다.

**Q. 이미 등록한 과제를 또 말하면요?**
- 기존 과제를 보여 주면서 "다른 과제인가요?"라고 묻습니다. 다른 과제라고 하면 이름 뒤에 번호를 붙여서(예: 알고리즘 과제 2) 구분해서 등록합니다.

**Q. 30분도 안 되는 짧은 일이 이어지면요?**
- 쉬는 시간만 두고 짧은 일이 이어져 있으면 "이어서 하시겠어요?"라고 묻습니다. 좋다고 하면 `기타 작업` 하나로 묶어서 쉬는 시간 없이 이어서 합니다. 어느 화면에서든 팝업으로 물어봅니다.

**Q. 사람마다 일하는 속도가 다른 건 반영하나요?**
- 끝낸 일에서 실제로 걸린 시간과 예상했던 시간을 비교해서, 다음에 같은 종류의 일은 시간을 조금 더 늘리거나 줄여서 예상합니다.

## 5. 아직 못 하는 것 (먼저 말하면 더 믿음이 갑니다)

**Q. 아직 안 되는 건 뭔가요?**
- 장소를 보고 일정을 넣는 기능은 아직 없습니다. 예를 들어 "학교 가는 날에 도서관 책 반납하기" 같은 건 안 됩니다.
- 하루에 쉴 수 있는 시간을 정해 두고 긴 일 뒤에 길게 쉬는 기능도 아직 없습니다. 지금은 일 사이에 정해 둔 시간만큼 쉽니다.
- 마감 때문에 위험한지를 더 정확하게 계산하는 건 앞으로 할 일입니다. 지금은 대략적인 계산입니다.
- 점수의 비율은 아직 사용자들의 실제 사용 기록으로 조정해 보지 않았습니다.

**Q. 마감 전에 꼭 끝낼 수 있나요?**
- 아닙니다. 시간이 모자라면 규칙을 깨지 않고 못 넣은 시간을 남겨 두고, 사용자에게 알려 줍니다.

**Q. 사용자가 많아지면요?**
- 지금은 해커톤용이라 파일 하나에 저장합니다. 사용자가 많아지면 데이터베이스가 필요합니다.

## 이렇게 말하면 안 돼요

- "논문에 나온 공식이다", "가장 좋은 값이다", "검증됐다"
- "마감 전에 무조건 끝난다"
- "장소를 보고 정한다", "쉬는 시간 총량을 정한다" (아직 없음)
- "AI는 항상 맞다" → "서버가 확인하고 틀리면 다시 시키는 구조"라고 말하세요.
