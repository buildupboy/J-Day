# J-Day 스케줄링 발표 예상 질문 (Q&A)

답변은 **현재 코드에 실제로 구현된 것만** 기준으로 썼습니다. 아직 없는 기능은 "향후 계획"으로 답하세요.

---

## 1. 우선순위 점수

**Q. 우선순위 공식의 출처/근거가 뭔가요?**
- 특정 논문의 공식이 아니라 팀이 직접 설계한 휴리스틱입니다.
- 마감이 빠른 것부터(EDF), 짧은 작업부터(SPT), 중요도와 긴급도를 함께 보는 아이젠하워 매트릭스의 아이디어를 하나의 가중합으로 합쳤습니다.
- 검증된 최적값이 아니라 조정 가능한 초기값이라고 말하세요.

**Q. 가중치 0.4 / 0.2 / 0.3 / 0.1은 왜 그렇게 정했나요?**
- 마감 임박 > 중요도 > 작업량 > 작업 길이 순으로 보려고 정했습니다.
- 통계나 사용자 실험으로 검증한 값은 아닙니다. "마감이 하루 늦어도 훨씬 중요한 작업이 먼저 가는지" 같은 시나리오를 테스트로 확인했습니다.

**Q. 마감이 하루 차이인데 훨씬 중요한 작업이 있으면 어떻게 되나요?**
- 점수로 비교하기 때문에 중요도가 높으면 마감이 하루 늦어도 먼저 배치될 수 있습니다. (마감만으로 줄 세우지 않습니다.)

**Q. 점수가 같으면요?**
- 마감이 빠른 순 → 중요도가 높은 순 → 남은 시간이 짧은 순 → 입력 순서입니다.

**Q. 마감이 이미 지난 작업은요?**
- 점수 100으로 고정해서 가장 먼저 다룹니다. 다만 과거에는 배치할 수 없어서 미배치로 남을 수 있습니다.

**Q. 480분은 뭔가요?**
- 하루에 현실적으로 쓸 수 있는 작업 시간을 8시간으로 가정한 값입니다. 실제 빈 시간은 반영하지 않는 근사식이고, 정확한 여유시간(slack) 계산은 향후 개선점입니다.

## 2. AI 역할과 신뢰성

**Q. 왜 규칙 기반으로 안 하고 AI가 시간을 배치하나요?**
- 앞뒤 일정과의 어울림, 운동 뒤 정리 시간, 긴 작업을 며칠에 나누기 같은 상황 판단은 고정 규칙으로 쓰기 어려워서 AI가 맡도록 했습니다.
- 스케줄러는 우선순위·남은 작업량·빈 시간·제약을 정리하고, AI가 배치하고, 서버가 검증합니다.

**Q. AI가 틀린 시간을 주면 어떻게 하나요?**
- 서버가 검증해서 규칙을 어기면 거절하고, AI에게 오류를 알려 한 번 더 다시 요청합니다. 그래도 안 되면 기존 일정을 유지합니다.
- 서버가 확인하는 것: 고정 일정·수면·지정 휴식 겹침, 작업끼리 겹침, 마감, 지난 시간, 한 번에 연속 작업 상한, 하루 작업량 한도, 작업 사이 휴식, 남은 작업량 초과, 하위작업 순서.

**Q. AI가 시간을 마음대로 고치지는 않나요?**
- 서버는 AI가 정한 시각을 자동으로 고치지 않습니다. 맞으면 저장하고 틀리면 거절합니다.

**Q. AI 응답이 느리면요?**
- 과제는 먼저 저장하고 일정 배치는 서버가 뒤에서 처리합니다. 시간이 초과돼도 과제는 남아 있고 "다시 배치" 버튼으로 재시도할 수 있습니다.
- 실제 소요 시간을 측정한 수치는 아직 없습니다. 서버 로그로 단계별 시간을 확인할 수 있습니다.

**Q. API 키는 안전한가요?**
- 키는 백엔드의 환경변수로만 읽고 프론트엔드에는 두지 않습니다.

## 3. 사용자 설정과 규칙

**Q. 하루 작업량 한도는 어떻게 지키나요?**
- 마이에서 고른 시간(2/4/6/8시간)을 넘기면 서버가 AI 결과를 거절합니다. 이미 배치된 작업과 완료 기록도 합쳐서 계산합니다. 고정 일정은 한도에 포함하지 않습니다.
- 한도를 낮추면 마감 안에 못 끝낼 수 있고, 그때는 미배치로 남습니다.

**Q. 휴식은 어떻게 처리하나요?**
- 작업 사이에 설정한 휴식 시간을 둡니다. 고정 일정 뒤에는 이동 시간과 휴식 중 큰 쪽을 비우도록 했습니다.
- 이동 시간이 있는 고정 일정은 서버가 점유 구간으로 강제하고, 일정 성격에 따른 추가 여유는 AI가 판단합니다(서버가 정확한 분량을 검증하지는 않습니다).

**Q. 큰 작업이 마감 한참 전인데 하루에 몰아서 들어가지는 않나요?**
- 프롬프트에 "마감까지 가능한 날 수로 하루 목표량을 계산해 고르게 나누고, 같은 작업을 하루에 연달아 붙이지 않는다"는 규칙을 넣었습니다. 서버가 강제하는 규칙은 아니고 AI가 따르는 규칙입니다.

**Q. 쉬는 날은 지원하나요?**
- 네. "토요일은 쉬고 싶어" 같은 요청을 날짜별 휴무로 처리해 그날에는 새 작업을 넣지 않습니다. 고정 일정과 기존 기록은 그대로 둡니다.

## 4. 입력과 사용성

**Q. 말로 여러 과제를 한 번에 등록할 수 있나요?**
- 네. 한 문장에 여러 과제를 말하면 과제별로 나눠 등록합니다. 마감이 없는 과제만 골라서 되묻습니다.

**Q. 예상 소요시간을 말하지 않으면요?**
- 시간을 말하지 않은 과제는 저장 전에 한 번에 되묻습니다. "제이가 정해줘"라고 하면 AI가 추정하고 하위작업으로 나눕니다. 예상 시간은 5분 단위입니다.

**Q. 이미 등록한 과제를 또 말하면요?**
- 기존 과제 카드를 보여 주고 "다른 과제인가요?"라고 묻습니다. 다르다고 하면 제목 뒤에 번호를 붙여(예: 알고리즘 과제 2) 구분해 등록합니다.

**Q. 30분 미만 작업이 이어지면요?**
- 쉬는 시간만 두고 이어진 짧은 작업이 있으면 "이어서 하시겠어요?"라고 묻고, 수락하면 `기타 작업` 하나로 묶어 쉬는 시간 없이 이어 배치합니다. 어느 화면에서든 팝업으로 알립니다.

**Q. 개인차(일을 빨리/느리게 하는 사람)는 반영하나요?**
- 완료한 작업의 실제 시간과 예상 시간의 비율을 유형별로 계산해, 이후 같은 유형의 예상 시간에 보정을 적용합니다.

## 5. 한계와 향후 계획 (먼저 말하면 신뢰도가 올라갑니다)

**Q. 아직 안 되는 것은요?**
- 장소를 보고 배치하기(예: 학교 가는 날에 도서관 책 반납)는 아직 없습니다.
- 하루 휴게 시간 총량을 정해 긴 작업 뒤에 길게 쉬는 방식은 아직 없습니다. 지금은 작업 사이 휴식을 설정값만큼 둡니다.
- 마감 위험도(여유시간 기반)는 근사식 수준이고, 정확한 계산은 향후 과제입니다.
- 가중치는 사용자 데이터로 아직 조정하지 않았습니다.

**Q. 마감 전에 항상 끝낼 수 있나요?**
- 아닙니다. 시간이 부족하면 규칙을 어기지 않고 미배치로 남기고 사용자에게 알립니다.

**Q. 서비스 규모가 커지면요?**
- 현재는 해커톤용으로 JSON 파일에 저장합니다. 사용자가 많아지면 DB가 필요합니다.

## 하면 안 되는 말

- "논문/표준 공식을 썼다", "최적화됐다", "검증됐다"
- "마감 전에 반드시 끝낸다"
- "장소·휴게 총량을 반영한다" (아직 미구현)
- "AI가 항상 정확하다" (검증과 재시도가 있는 구조라고 말하세요)
